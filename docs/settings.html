Charge-Based LTE Formula (cktterr.c): For each energy-storage element with charge qn and current in, tol = max(abstol + reltol · max(|in|, |in−1|), reltol · max(|qn|, |qn−1|, chgtol) / hn), and the proposed step is hnext = (trtol · tol / max(abstol, cord · |DDord+1(q)|))1/ord, where c1 = 1/2, c2 = 1/12 (Trap) or 2/9 (Gear-2). Steps are rejected whenever min(2hn, hnext) ≤ 0.9 · hn (dctran.c:801).

5. Six Critical Porting Pitfalls for Fair Cross-Simulator Benchmarks

Common silent mismatches that skew wall-time comparisons by 2×–10×

1. Implicit maxstep = tstep Clamping

In ngspice (traninit.c:30), writing tran 150p 6.6u without a 4th argument silently caps CKTmaxStep = 150 ps (unless set nostepsizelimit is set). Spectre, Xyce, and LTspice default to tstop/50 or unconstrained steps. Always pass explicit maxstep / delmax = tstep (or run both simulators unconstrained) before comparing wall time.

2. Charge LTE (trtol=7) vs Voltage LTE (lteratio)

ngspice controls truncation error on element charge with trtol=7.0 and chgtol=1e-14 (which can over-step or under-step on sub-fF post-PEX parasitics). Spectre controls LTE directly on node voltages with lteratio=3.5 (moderate), while LTspice defaults to trtol=1 (far tighter than SPICE3's 7). Report accepted/rejected timepoints alongside wall time.

3. Gear-2 Damping vs Trap / Modified-Trap Ringing

All 7 ngspice-bench decks run Gear-2 (method=gear) to suppress 2-step trapezoidal ringing on switched-cap/digital edges. Spectre's default trap blends Trap and Gear-2, and LTspice's default modified trap applies post-filtering; use gear2only (Spectre) and method=gear (HSPICE/Xyce/LTspice) for identical numerical damping — especially on pll_ring_150m_4us where integrator damping shifts VCO lock frequency.

4. gmin Placement vs rshunt / gshunt

gmin=1e-12 is inserted across nonlinear junctions and transistor channels, whereas rshunt=1e12 (ti12_full_300ns, opa1k_pvt16) adds a 1 TΩ resistor from every analog node to ground to regularize floating post-PEX nodes. Similarly, cshunt maps to Spectre's cmin (node-to-ground cap), not a device junction parameter.

5. Legacy bypass=0 vs RUNLVL / FastSPICE

Stock ngspice-47 runs with legacy SPICE3 bypass=0 and full exact MNA Newton solves. HSPICE's default RUNLVL=3 and Spectre APS/XPS enable aggressive bypass, looser abstol=1e-9/vntol=5e-5, and circuit partitioning. Verify every ported run against the exact golden waveforms (SAR codes, PLL lock code, SDM PDM bits, RISC-V cycles) and report whether any approximate FastSPICE mode was enabled.

6. Hidden itl4 ≥ 100 Floor & LTspice Waveform Compression

ngspice silently raises any itl4 < 100 to 100 (niiter.c:47), so a deck omitting itl4 (like opa1k_pvt16) still gets 100 Newton iterations per step. When exporting waveforms from LTspice for compare_raw.py verification, always set .options plotwinsize=0 numdgt=15 so lossy 1st-order compression does not corrupt RMS metrics.

6. Verification, Pinning & Reproducibility Policy

Enforced automatically by scripts/run_bench.py and scripts/compare_raw.py

Single-Core Pinning & Core-Class Isolation

Every leaderboard entry runs strictly single-threaded (num_threads=1, OMP_NUM_THREADS=1, OMP_PROC_BIND=true) pinned to one logical CPU: taskset -c <cpu> on Linux; taskpolicy -c (with zero-memory register spinners for 3-tier intermediate clusters) on macOS Apple Silicon. Hybrid CPUs (Intel P/E/LP-E, ARM big.LITTLE, Apple P/E) report each core class independently.

Strict IEEE-754 Compliance (No -ffast-math)

Builds compiled with -ffast-math, -Ofast, or unsafe reciprocal/transcendental approximations are disqualified. Strict IEEE-754 double precision preserves NaN/Inf guards inside fetlim/pnjlim, prevents KLU pivot drift, and guarantees deterministic comparator and digital-state switching across CPUs. Permitted optimization flags: -O3 -fno-math-errno -fno-trapping-math -fno-semantic-interposition -flto.

Golden Reference Policy

Every run writes a binary IEEE-754 double .raw file verified against unmodified stock ngspice-47 baselines in golden/. For Probe and Hero decks, the leaderboard reference speedup is normalized to stock ngspice-47 Sparse 1c on Ryzen 9 7940HX; for the 51,670-equation riscv_picorv32_120ns scaling deck, the reference is stock ngspice-47 KLU 1c.

7. Empirical Cadence Spectre X 25.10 Calibration (Commercial GF180MCU PDK)

Measured on AMD EPYC 9684X (1c / +mt=1) with GF180MCU YI-141-SM064 Rev9 Spectre PDK

To compare ngspice fairly against commercial Cadence Spectre 25.10 using the official GlobalFoundries GF180MCU Spectre PDK (sw_stat_global=0, sw_stat_mismatch=0, matching open-source sm141064.ngspice to 6–7 digits on single-device DC IV and AC capacitances), we swept Spectre engines (++aps vs Spectre X +preset=cx/ax/mx) and error tolerances against Spectre X +preset=cx and ngspice-47 goldens.

Recommended ngspice-Matched Setting: +preset=ax -preset_override="reltol,vabstol,iabstol"

By default, Spectre X presets ignore deck reltol/vabstol/iabstol and enforce tighter 1e-3 / 1 μV / 1 pA floors (10–20× tighter than our ngspice decks). Passing -preset_override="reltol,vabstol,iabstol" honors each deck's exact ngspice tolerances while keeping Spectre X's analog-accurate ax solver (relref=sigglobal, lteratio=3.5, method=trap): 15–22% faster with 16/16 bit-exact SAR codes (67.5 ps EOC vs +preset=cx), exact PLL AFC lock parity, ti12 voltage RMS 2.12e-4, sdm16 DAC r=0.9991, and 3/3 cycle-exact RISC-V (rms 1.66e-4 vs ax).

Key Porting Findings Observed on Real Silicon Decks

(1) +preset=mx tradeoff: Relaxing relref from sigglobal (ax) to allglobal (mx) cuts runtime another 25–43% (matching 16/16 SAR codes and 3/3 RISC-V cycles), but shifts the sensitive 6-bit SAR AFC lock code in pll_ring_150m_4us by 5 codes and widens SAR EOC skew to 437–620 ps.
(2) Don't force gear2only in Spectre: Forcing method=gear2only + lteratio=1.0 + maxstep=tstep runs 1.5–2.5× slower and adds Gear-2 numerical damping delay (290–1214 ps EOC skew); dropping maxstep under gear2only loses 12-bit SAR bit-exactness.
(3) ++aps DC OP homotopy: On floating-node dynamic SAR ADCs, Spectre ++aps needs +fastdc (cutting DC OP from 313.8 s to 1.70 s), whereas Spectre X converges in 0.53 s automatically.
